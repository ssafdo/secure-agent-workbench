# Agent 知识整合路线

每一步先增加评测用例，再增加能力，最后记录失败归因。这样“学过的知识”会变成可验证的工程能力。

| 阶段 | Agent 知识 | 项目增量 | 完成定义 |
|---|---|---|---|
| 1 | Agent loop、工具系统、Plan-and-Solve、可观测性 | 当前本地 MVP | 工具权限与路径测试通过，demo 可回放 |
| 2 | LLM 基础、提示工程、结构化输出、ReAct | OpenAI-compatible provider 与 function calling | mock 测试覆盖解析错误、循环上限、超时 |
| 3 | 上下文工程、短期记忆、Reflection | 会话历史、压缩、失败后反思重试 | 长上下文评测对比成本和成功率 |
| 4 | RAG、语义记忆、引用 | 已完成词法基线、可选本地 embedding、混合重排和引用校验；语义记忆待实现 | 8 条固定集已量化 Recall@K、MRR、引用正确率和无依据拒答，混合 NiceEval 已通过 |
| 5 | MCP 与协议 | 已完成官方 SDK stdio client、工具发现、只读白名单和 schema gate | 恶意描述、重复名、危险 annotation、参数越权、超时/清理和超大输出均有测试，MCP NiceEval 已通过 |
| 6 | 多 Agent、路由和协作 | 已完成确定性 supervisor、置信度、专业 Agent、私有盲测和独立标注协议 | 6 条端到端消融成功率从 0.5 提升到 1.0；50 条策划集准确率 1.0；自然任务结论仍待授权数据 |
| 7 | Web 应用与附件桥 | Open WebUI 适配、上传与回传 | 用户/项目/会话归属校验通过 |
| 8 | 生产隔离 | 容器 executor、网络策略、资源限额 | 不可信代码逃逸测试和并发压测通过 |
| 9 | 性能评估 | eval runner、成本、延迟、失败分类 | 至少 20 个案例和一份消融报告 |

## 不建议过早集成的内容

- 在没有基线评测前增加多个 Agent，会让问题归因更困难。
- 在没有权限模型前接入 MCP，会扩大工具攻击面。
- 在没有附件归属模型前挂载 Open WebUI 数据目录，会造成跨用户泄露风险。
- 在没有容器边界前执行 Shell 或用户代码，不符合参考架构的安全目标。
