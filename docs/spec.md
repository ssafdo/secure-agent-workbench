# 产品规格：Secure Agent Workbench

## 1. 项目定位

为小型可信团队提供一个可审计的多 Agent 工作台。用户在统一入口创建任务，平台为每个用户、对话和功能建立隔离项目，由专业 Agent 在受控工具和工作区内完成研究、文档、数据分析等任务。

## 2. 第一阶段用户故事

1. 用户运行一个研究任务，系统只能读取当前项目中的 `.txt` 和 `.md` 文件。
2. Agent 在写入报告前必须获得显式批准。
3. 用户能回看每次工具调用、耗时、结果状态和错误类型。
4. 两个不同用户或对话不会得到相同项目目录。
5. 恶意路径无法越过项目根目录读取或写入文件。

## 3. 功能范围

### 已纳入 Phase 1

- CLI 通道
- 工作区和会话身份
- 工具白名单与权限策略
- 确定性研究 Agent
- JSONL 执行轨迹
- 单元与安全测试

### 当前仍暂不纳入

- 外部 Open WebUI 前端定制与账号体系
- 用户登录和数据库映射
- 生产级对象存储、签名下载链接和二进制附件解析
- microVM 执行器与面向不可信公网用户的执行服务
- A2A 与跨服务 Agent 协作
- 多租户并发和分布式锁

### Phase 2 当前增量

- 厂商无关的结构化模型响应与 tool-call 协议
- 可离线测试的 FakeLLM 和 ReAct 循环
- 模型调用数、轮次、token 与金额预算
- 模型事件脱敏 trace 与 NiceEval 对照基线
- OpenAI Responses API 兼容 Provider、严格 function calling 与 reasoning item 续传
- 请求超时、瞬态错误重试、进程内熔断和 hosted HTTP 路由
- 模型密钥仅由服务端环境注入，默认仍不启用网络 Provider

### Phase 6 当前增量

- Python 服务同源提供无需构建链的研究工作台
- 任务与 Markdown/TXT 资料编辑，DeepSeek 与离线 ReAct 模式切换
- 连续会话版本、报告预览、工具轨迹、Token 和上下文诊断
- 浏览器内容安全策略、无 HTML 注入的报告渲染和移动端布局

### Phase 7 当前增量

- 浏览器本地选择 `.md/.txt` 并读取为当前任务资料，不向客户端暴露宿主机路径
- 同名附件更新、最多 20 份、单份最多 200 KB；服务端重复执行大小校验
- DeepSeek/离线数据边界提示，以及 UTF-8 Markdown 报告下载
- `file://` 入口自动跳转到受支持的 loopback 同源服务地址

### Phase 8 当前增量

- 可选 Docker 执行器默认不注册；启用时镜像必须使用本地 `sha256:<image-id>` 或仓库 `name@sha256:<digest>`，并禁止运行阶段自动拉取
- 工具只接受结构化 `argv` 和可执行文件白名单，不接受 Shell 命令字符串
- 容器强制无网络、只读根文件系统、非 root、capability 清空、`no-new-privileges` 和 CPU/内存/PID/输出上限
- 仅挂载项目 `inputs`（只读）、`work` 和 `outputs`，超时后按随机容器名强制回收
- `container-doctor` 机器可读诊断；没有 Docker daemon 或本地摘要镜像时明确返回未就绪

### Phase 12 当前增量

- `search_text` 只读工具固定扫描当前项目 `inputs` 下的 Markdown/TXT，不接受外部目录或宿主路径
- 本地分块与 BM25 风格词法排序，同时支持英文 token 与中文双字片段
- 检索结果包含路径、起止行、正文、分数和指令风险信号；Agent 写报告前重新核对引用与源文
- `retrieval` 引擎无相关证据时明确拒答，不调用外部模型，不支持持久会话
- Prompt Injection 模式只用于诊断；真正安全边界仍是 Runtime 权限、工具白名单和隔离执行器

### Phase 13 当前增量

- 本地 embedding 是可选能力；默认零依赖词法路径保持可用
- 模型只从服务端配置的本地目录加载，仓库提交与运行文件 SHA-256 固定，请求期间不联网下载
- 混合分数组合归一化 BM25 风格分数与余弦相似度，并对纯语义候选使用相关阈值
- API 与报告必须公开实际检索模式；初始化或编码失败必须显示为 `lexical-fallback`
- 固定基准必须同时报告 Recall@1、Recall@3、MRR、引用正确率和无依据拒答准确率

### Phase 14 当前增量

- 使用官方 Python MCP SDK 接入 stdio server，不实现私有协议变体
- server 与工具仅能由服务端操作员配置；浏览器/API 不能指定 command、环境或工具
- 首版只接纳显式 allowlist 中的只读、非破坏、非开放世界工具
- 远端 description 不进入模型上下文；输入 schema、调用实参和调用前工具指纹都必须验证
- MCP 调用必须经过 `AgentRuntime`，并受到步骤预算、项目锁、超时、输出上限和脱敏 trace 约束

### Phase 15 当前增量

- `supervisor` 引擎只做意图路由，不直接调用任何工具
- Synthesis 专家用于全量资料与跨文档任务，Retrieval 专家用于证据查证、引用和无依据拒答
- 委派必须复用同一个 Runtime，不得重置权限、步骤预算、项目锁或 trace
- API 必须公开专业 Agent 和稳定原因码，但 trace 不保存用户任务正文
- 固定消融必须用最终报告行为判分，并同时报告单 Agent 与 Supervisor 成功率、工具调用数

### Phase 16 当前增量

- 路由响应公开 `high|medium|low` 置信度及 synthesis/retrieval 信号数，但不公开或记录任务正文
- 50 条中英领域路由集至少覆盖证据、无依据问题、综合、比较、复合意图、未知意图和对抗 Agent 名称
- 路由基准报告混淆矩阵、语言/类别切片、加权错误和逐条错误列表
- 路由分类门禁与 6 条真实 Agent 端到端消融必须保持独立，禁止用标签准确率代替最终任务成功率

### Phase 17 当前增量

- 自然任务盲测数据必须逐条人工去敏和审核，并使用不含用户、会话或工单标识的匿名 ID
- 封存必须绑定完整数据集和当前 Supervisor 路由源码哈希；任一变化都使旧 manifest 失效
- 评估结果不得包含任务正文，只能输出匿名 ID、人工标签、预测、置信度和聚合指标
- 私有数据集、manifest 与结果不得提交 Git、上传 NiceEval 或进入 CI；CI 只运行协议和失败路径测试
- 自动敏感信息扫描是辅助门禁，不能替代用户授权、人工去敏和数据保留政策

## 4. 不可变约束

- 客户端不得指定宿主机绝对目录。
- executor 不挂载平台数据库、Docker socket 或宿主机密钥。
- 网络、Shell 和写工具默认关闭或需要更高权限；宿主 Shell 永不提供给 Agent。
- trace 不保存密钥，后续接入 LLM 时需增加 prompt 脱敏。
- 上传文件必须在桥接层重新验证用户、会话和项目归属。

## 5. Phase 1 验收标准

- 一条命令运行测试，一条命令运行 demo。
- 路径穿越、跨项目读取和未批准写入均被拒绝。
- 成功、失败、拒绝三种工具调用都有 trace。
- demo 在无网络、无 API key 的环境生成可读报告。

## 6. Phase 8 验收标准

- 默认注册表没有执行工具，默认项目没有 `execute` 权限。
- 普通 tag、Shell 字符串、非白名单可执行文件和未批准调用均被拒绝。
- Docker 命令包含全部隔离标志，且没有 `.agent`、Docker socket 或宿主密钥挂载。
- 超时触发强制回收，stdout/stderr 超限会截断并显式标记。
- 只有 `container-doctor` 返回 `ready: true` 时，才允许记录真实容器冒烟测试为通过。
